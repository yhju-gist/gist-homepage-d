# D안 운영·유지보수 인계서 (2026-11-18)

D안은 화면 시안이지만, 실제 운영 때 필요한 **자동 연결·관리·점검** 방식을 함께 돌려 보고 있습니다.
이 문서는 담당자가 바뀌어도 그대로 이어서 운영할 수 있도록 "무엇이 돌고, 어디서 자료가 오고, 고장 나면 무엇을 보면 되는지"를 적은 것입니다.

## 1. 저절로 바뀌는 것 (사람이 손대지 않아도 됨)

| 무엇 | 어디서 가져오나 | 만드는 파일 | 화면에 나오는 곳 |
|---|---|---|---|
| 공지·학사일정·GIST 소식 | 현행 대표 홈페이지 공개 게시판 | `data/live.json` | 첫 화면 공지·학사일정, GIST TODAY ‘새 소식’, 통합검색 |
| 학과·연구소·센터 26곳 최근 글 | 각 홈페이지 첫 화면(또는 공지 목록·RSS) | `data/sites.json` | 학과 화면 ‘학과 홈페이지 최근 글’, 대학·학과 목록 ‘새 글 날짜’, 부속기관·부설 연구소 카드, 통합검색, `#sync` 홈페이지 연결 현황 |
| GIST 전체 새 글 RSS | 위 두 파일 | `feed_all.xml` | 첫 화면 ‘새 소식 받기’, 언론·기관 구독용 |
| 공식 SNS 최근 글 | 유튜브·인스타그램·페이스북 공식 경로 | `data/sns.json` | 첫 화면 SNS 줄 |

- 가져오는 스크립트: `scripts/gist_fetch.py`, `scripts/sites_fetch.py`, `scripts/sns_fetch.py` (표준 파이썬만 씀)
- 돌리는 작업: `.github/workflows/gist.yml`(1시간마다), `.github/workflows/sns.yml`(30분마다)
- 제목·날짜·주소만 가져옵니다. 본문과 작성자 이름은 가져오지 않습니다.
- 파일마다 `checked`(내용이 마지막으로 바뀐 때)와 `tried`(마지막으로 가져와 본 때)를 따로 적습니다. 화면의 ‘마지막 확인’은 `tried`를 씁니다(11.22. 공지·학사일정 자료에도 추가).
- 가져오기에 실패하면 지난번 목록을 그대로 두고 ‘가져오기 실패’로 표시합니다. 화면이 비지 않습니다.

## 2. 꼭 알아야 할 한계

- **GitHub 무료 예약 작업은 정시에 돌지 않습니다.** 11.16.~17. SNS 작업은 33시간 동안 5번 돌았고, 11.17. 21:36에 켠 gist.yml은 11.18. 03:41까지 예약 실행이 한 번도 없었습니다. 그동안은 담당자 PC에서 같은 스크립트를 직접 돌려 올렸습니다.
- 그래서 자동 작업이 3시간 넘게 돌지 않으면 `#sync` 화면과 관리자 모드 ‘연결 상태’ 탭에 경고가 뜹니다.
- **학교 서버로 옮길 때는** 같은 스크립트를 서버 예약 작업(cron, 매시 정각)으로 돌리면 됩니다. 스크립트는 그대로 씁니다.

## 3. 관리자 모드에서 할 일

- 공지·학사일정: 기본은 ‘자동 연결’ 켜짐. 행사 공지처럼 따로 강조할 때만 끄고 직접 적습니다. 다른 칸을 저장해도 자동 갱신은 멈추지 않습니다.
- ‘연결 상태’ 탭: 자동 자료가 언제 마지막으로 들어왔는지, 가져오지 못한 홈페이지와 1년 넘게 새 글이 없는 홈페이지를 봅니다.

## 4. 고장 났을 때 보는 순서

1. `#sync` 화면 위쪽 숫자(이어 받기 성공 몇 곳)와 ‘마지막 확인’ 시각을 봅니다.
2. ‘가져오기 실패’인 곳: 그 홈페이지가 열리는지 브라우저로 확인합니다. 학교 서버 인증서 연결이 느린 곳(예: 전기전자컴퓨터공학과, 11.17. 23:36 시간 초과 → 00:39 회복)은 다음 시도에 저절로 돌아옵니다.
3. 여러 번 연속 실패하면 그 홈페이지 첫 화면 모양이 바뀐 것일 수 있습니다. `scripts/sites_fetch.py`의 `SITES` 줄에서 그 곳의 ‘읽을 주소’를 공지 목록 주소나 RSS 주소로 바꿉니다.
4. ‘마지막 확인’이 몇 시간째 그대로면 자동 작업이 돌지 않은 것입니다. GitHub 저장소의 Actions 화면에서 gist.yml을 직접 실행하거나, PC에서 아래를 돌린 뒤 바뀐 파일을 올립니다.

```
python scripts/gist_fetch.py
python scripts/sites_fetch.py
```

## 5. 홈페이지를 더하거나 뺄 때

`scripts/sites_fetch.py`의 `SITES` 목록에 한 줄을 더하거나 뺍니다.
형식: `("영문id","이름","학과|연구소·센터|교육·지원","단과대학 또는 빈칸","홈페이지 주소", None 또는 ("읽을 주소","html|rss"))`
주소는 `*.gist.ac.kr`만 화면에 나옵니다(다른 주소의 글은 버립니다).
학과를 더할 때는 화면의 학과 코드(`DURL`)와 같은 영문 id를 써야 학과 화면과 이어집니다.
